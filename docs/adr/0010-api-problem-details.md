# ADR-0010: Versioned API with RFC 9457 problem details

- Status: Accepted
- Date: 2026-10-08

## Context
API clients need a stable, predictable contract for success and error responses.

## Decision
- Routes under `/api/v1`, defined per module in `routes/api.php`, auth via Sanctum, rate-limited by the `api` limiter.
- Success: Laravel API Resources (`{"data": ..., "links": ..., "meta": ...}` for collections).
- Errors: `application/problem+json` with `type`, `title`, `status`, `detail`, `instance`, plus `errors` (validation) and `correlation_id`. Rendered centrally by `App\Shared\Http\ProblemDetails` from the exception handler.
- Query contract: `?page[number]=&page[size]=` is *not* used; we use Laravel's native `?page=&per_page=` (max 100), `?filter[field]=`, `?sort=field,-other`. Documented in `docs/api.md`.
- OpenAPI generated by `dedoc/scramble` at `/docs/api` (local, or behind `viewApiDocs` gate).

## Consequences
One error format everywhere; web requests still get Blade error pages.
